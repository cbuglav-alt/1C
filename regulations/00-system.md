# Как устроена система регламентов

## Принципы

**1. Один источник правды.** Обязанность по клиенту существует ровно в одном месте —
в каталоге задач. Не в голове бухгалтера, не в личном файле Excel, не в переписке.
Изменилось законодательство — правится каталог, и изменение автоматически доезжает
до всех клиентов, к которым оно относится.

**2. Задача порождается правилом, а не человеком.** Бухгалтер не решает, какие задачи
у него в этом месяце. Список собирается из профиля клиента по формальному правилу.
Это убирает главный риск агентства — «забыли, что у этого клиента появился НДС».

**3. Внутренний срок всегда раньше законного.** Законный срок — это срок отказа.
Работаем по внутреннему сроку с буфером. Задача, сданная в законный срок день в день,
считается просроченной по регламенту.

**4. Задача закрывается результатом, а не действием.** «Сдал РСВ» — не результат.
Результат — положительный протокол от ФНС, подшитый к задаче. Поэтому у критичных
задач есть парная задача контроля квитанций (`QC-20`).

**5. Изменение профиля клиента — событие.** Клиент нанял первого сотрудника,
перешёл на НДС, открыл обособку — это не «учтём в следующем месяце», а немедленное
обновление карточки клиента и перегенерация плана.

## Уровни системы

```
┌─────────────────────────────────────────────────────────────┐
│ УРОВЕНЬ 1. Методология                                       │
│ Каталог задач, чек-листы, учётная политика, нормативка       │
│ Владелец: главный бухгалтер-методолог                       │
├─────────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 2. Планирование                                      │
│ Профили клиентов → генерация плана → распределение нагрузки  │
│ Владелец: руководитель отдела                               │
├─────────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 3. Исполнение                                        │
│ Задачи в CRM, чек-листы, коммуникация с клиентом            │
│ Владелец: ведущий бухгалтер клиента                         │
├─────────────────────────────────────────────────────────────┤
│ УРОВЕНЬ 4. Контроль                                          │
│ SLA-дашборд, выборочный контроль качества, разбор инцидентов │
│ Владелец: руководитель отдела + главный бухгалтер           │
└─────────────────────────────────────────────────────────────┘
```

## Месячный цикл

| Когда | Что происходит | Кто |
|---|---|---|
| 23–25 числа | Актуализация профилей клиентов: изменения режима, сотрудников, услуг | Ведущий бухгалтер |
| 25 числа | Генерация плана на следующий месяц, проверка нагрузки | Руководитель отдела |
| 26–27 числа | Загрузка задач в CRM, распределение, согласование переработок | Руководитель отдела |
| 28 числа | Планы у бухгалтеров на руках; при перегрузе — перераспределение | Руководитель отдела |
| 1 число | Старт исполнения | Все |
| В течение месяца | Ежедневный контроль просрочек, эскалации | Руководитель отдела |
| 5 числа след. месяца | Разбор закрытого месяца: просрочки, инциденты, корректировка каталога | Руководитель + главбух |

## Что система не делает

- Не заменяет профессиональное суждение. Каталог даёт перечень и сроки, а не готовое решение
  по спорной операции. Для этого есть эскалация к главному бухгалтеру.
- Не отслеживает разовые задачи (требования ФНС, блокировки счетов, встречные проверки).
  Они заводятся вручную и живут по отдельному SLA — см. [эскалации](08-escalations.md).
- Не следит за законодательством сама. Актуализацию каталога делает человек по регламенту
  в [разделе 3](03-task-catalog.md#актуализация).
