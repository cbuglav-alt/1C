# Настройка Finkooper

> Точные названия полей, разделов и наличие массового импорта зависят от версии
> и тарифа вашего аккаунта. Ниже — модель данных и правила, которые нужно
> сопоставить с интерфейсом при первой настройке. Сопоставление делается один раз,
> фиксируется в этом документе и дальше не меняется.

## Два способа вести задачи

| | **А. Шаблоны внутри CRM** | **Б. Внешняя генерация + загрузка** |
|---|---|---|
| Как работает | Задачи создаются автоповтором по шаблонам, настроенным в CRM | План собирается генератором и загружается в CRM файлом раз в месяц |
| Плюс | Не нужен внешний инструмент | Правила применимости, авторасчёт переносов, расчёт нагрузки до загрузки |
| Минус | Нет условной логики «нужна ли задача этому клиенту» | Нужен шаг генерации и загрузки |
| Когда выбирать | До 15 клиентов, однородные профили | От 15 клиентов или разные режимы и профили |

**Рекомендация: гибрид.** Повторяющийся месячный контур (`DOC-*`, `ACC-*`, `PAY-*`) —
шаблонами внутри CRM, он одинаков из месяца в месяц. Отчётность и налоги (`REP-*`, `TAX-*`),
где состав зависит от профиля клиента и сроки плавают из-за переносов, — генератором.
Так вы не дублируете рутину вручную и не теряете условную логику там, где она критична.

## Соответствие модели и сущностей CRM

| Наша модель | Сущность в CRM | Примечание |
|---|---|---|
| Карточка клиента (`clients.csv`) | Клиент / организация | `client_id` пишем в поле внешнего идентификатора |
| Признаки профиля (`nds`, `employees`, `ved`…) | Пользовательские поля или теги клиента | Нужны, чтобы фильтровать и сверять с генератором |
| Задача из каталога | Задача | Название с кодом в начале: `[REP-NDS] Декларация по НДС за III квартал 2026` |
| `role` → фамилия | Ответственный | Один ответственный, без соисполнителей |
| `internal_due` | Срок / дедлайн задачи | По нему считается просрочка |
| `legal_due` | Пользовательское поле «Законный срок» | Только для справки и разбора инцидентов |
| `block` | Категория / проект / группа задач | Для группировки в списке бухгалтера |
| `crit` | Приоритет (A → высокий, B → средний, C → низкий) | Правило эскалации завязано на приоритет |
| `effort_min` | Плановое время | Основа отчёта по нагрузке и рентабельности клиента |
| `checklist` | Чек-лист внутри задачи | Пункты копируются из `regulations/checklists/` |
| Тег месяца `2026-10` | Метка / тег | Позволяет массово находить и закрывать период |

## Правила именования задач

Формат: `[КОД] Название задачи за период`

```
[REP-RSV] РСВ за 9 месяцев 2026
[TAX-NDFL-N1] Уведомление по НДФЛ за период с 1 по 22 число
[ACC-50] Экспресс-проверка и закрытие месяца в 1С
```

Код в начале — обязателен. По нему ищутся все однотипные задачи по всем клиентам,
считается статистика просрочек по видам задач и связываются задачи с каталогом
при изменении регламента.

## Обязательные поля задачи

Задача не считается корректно заведённой, если не заполнено:

- Клиент
- Ответственный (ровно один)
- Срок (внутренний)
- Приоритет
- Категория
- Чек-лист — для всех задач категории A

## Порядок ежемесячной загрузки

```
25 числа                26 числа                 27 числа              28 числа
Актуализация    ──►    Генерация плана   ──►    Загрузка в CRM  ──►   Планы у команды
карточек               и проверка нагрузки      и распределение       на руках
```

1. **Актуализация карточек.** Ведущие бухгалтеры проверяют профили своих клиентов
   и вносят изменения (задача `INT-30`).
2. **Генерация.**
   ```bash
   python3 tools/generate_plan.py --month 2026-11 --clients data/clients.csv
   ```
3. **Проверка нагрузки.** Открыть `out/plan_2026-11.md`, раздел «Нагрузка по сотрудникам».
   Норматив — не более 130 плановых часов в месяц на бухгалтера. Превышение —
   перераспределение или согласование переработки до загрузки, а не после.
4. **Загрузка.** Файл `out/crm_import_2026-11.csv` в импорт задач. При первой загрузке
   сопоставьте колонки с полями CRM и зафиксируйте маппинг здесь.
5. **Контроль загрузки.** Число задач в CRM с меткой месяца = число строк в `plan_*.csv`.
   Расхождение — разбираться до 28 числа.

**Если массовый импорт недоступен** на вашем тарифе: `crm_import_*.csv` открывается
в Excel и используется как рабочий лист для ручного заведения, либо загружается
через API интеграцией. Переходить на ручное заведение без файла-источника нельзя —
теряется контроль полноты.

## Шаблоны задач внутри CRM (контур А)

Настраиваются один раз на клиента при онбординге. Для каждой задачи месячного контура:

| Параметр шаблона | Значение |
|---|---|
| Название | `[КОД] Название` из каталога |
| Периодичность | Ежемесячно |
| День создания | `start` из каталога (обычно 1 число) |
| День срока | `int_due_day` из каталога |
| Ответственный | По роли из карточки клиента |
| Чек-лист | Из `regulations/checklists/` |

Перечень задач, которые имеет смысл вести шаблонами CRM:
`DOC-10`, `DOC-20`, `DOC-40`, `DOC-50`, `ACC-10`, `ACC-20`, `ACC-50`, `ACC-70`,
`HR-10`, `PAY-10`, `PAY-20`, `PAY-30`, `CLI-10`, `CLI-30`, `QC-20`.

Всё остальное — генератором, потому что зависит от профиля клиента или имеет
законный срок с переносом.

## Представления, которые должны быть настроены

| Представление | Фильтр | Кто смотрит | Зачем |
|---|---|---|---|
| **Мой месяц** | Ответственный = я, метка = текущий месяц, группировка по клиенту | Бухгалтер | Основной рабочий экран |
| **Моя неделя** | Ответственный = я, срок ≤ +7 дней, сортировка по сроку | Бухгалтер | Ежедневная работа |
| **Красная зона** | Приоритет = высокий, срок ≤ +3 дней, статус ≠ выполнена | Руководитель | Предотвращение просрочек |
| **Просрочено** | Срок < сегодня, статус ≠ выполнена | Руководитель | Ежедневный контроль, эскалации |
| **По клиенту** | Группировка по клиенту, метка = месяц | Бухгалтер, главбух | Ответ клиенту «что у нас по статусу» |
| **Нагрузка** | Сумма планового времени по ответственным | Руководитель | Планирование и наём |
| **Контроль качества** | Категория = Контроль, ответственный = главбух | Главбух | Выборочные проверки |

## Статусы задач

| Статус | Значение | Кто ставит |
|---|---|---|
| Новая | Создана, не начата | Система |
| В работе | Взята в работу | Исполнитель |
| Ждёт клиента | Заблокирована отсутствием документов или решения клиента | Исполнитель, с обязательным комментарием и датой запроса |
| На проверке | Выполнена, ждёт контроля главбуха | Исполнитель |
| Выполнена | Результат получен и приложен | Исполнитель или главбух |
| Отменена | Задача неприменима | Руководитель, с указанием причины |

**«Ждёт клиента» не останавливает срок.** Задача остаётся в плане и попадает в просрочку,
если срок наступил. Это сознательно: блокировка со стороны клиента должна быть видна
руководителю и превращаться в договорную эскалацию, а не тихо висеть.

**Отмена задачи** — только через руководителя. Массовая отмена однотипных задач —
сигнал, что каталог или профиль клиента не соответствуют реальности: разбираем причину
и правим источник, а не отменяем каждый месяц заново.

## Чек-лист первичной настройки

- [ ] Заведены пользователи и роли, у каждого проставлена специализация
- [ ] Все клиенты перенесены с заполненным `client_id` и признаками профиля
- [ ] Созданы категории задач по блокам каталога
- [ ] Созданы пользовательские поля: «Законный срок», «Код задачи», «Плановое время»
- [ ] Настроены 7 представлений из таблицы выше
- [ ] Настроены шаблоны месячного контура для каждого клиента
- [ ] Загружены чек-листы для всех задач категории A
- [ ] Сделан пробный импорт на 1 клиенте, маппинг колонок зафиксирован в этом документе
- [ ] Проведена первая полная генерация и загрузка, число задач сверено
