# Профиль клиента и классификатор

Профиль — это набор признаков, из которых система выводит перечень задач.
Ошибка в профиле = отсутствующая или лишняя задача, поэтому карточка клиента —
такой же контролируемый объект, как сама отчётность.

## Поля карточки

| Поле | Значения | Что включает |
|---|---|---|
| `client_id` | `CL-001` | Внутренний идентификатор, связь с CRM |
| `name` | текст | Наименование как в CRM |
| `inn` | 10 / 12 цифр | Контроль при сверках с ФНС |
| `opf` | `ООО`, `ИП` | Разные сроки деклараций, бухотчётность, фиксированные взносы |
| `sno` | `ОСНО`, `УСН-Д`, `УСН-ДР`, `ПСН`, `АУСН`, `ЕСХН` | Ключевой признак: определяет налоговый блок |
| `nds` | `1` / `0` | Декларация и уплата НДС, сверка книг покупок и продаж |
| `employees` | число | Весь зарплатный и кадровый блок |
| `gph` | `1` / `0` | Договоры ГПХ: НДФЛ, взносы, персведения даже при 0 сотрудников |
| `kassa` | `1` / `0` | Кассовая дисциплина, сверка с ОФД |
| `ved` | `1` / `0` | Валютный контроль, ГТД, курсовые разницы, НДС при импорте |
| `prop` | `1` / `0` | Имущественные налоги: транспорт, земля, недвижимость |
| `alco` | `1` / `0` | Декларации по обороту алкоголя, ЕГАИС |
| `mark` | `1` / `0` | Маркировка и прослеживаемость, отчёт по РНПТ |
| `op` | `1` / `0` | Обособленные подразделения: отдельная уплата НДФЛ и отчётность |
| `accountant` / `payroll` / `chief` | ФИО | Кто получает задачи по ролям |
| `tariff` | `Базовый`, `Стандарт`, `Полный` | Объём услуг по договору |
| `advance_day` / `salary_day` | 1–31 | Дни выплаты аванса и зарплаты по трудовому договору |
| `status` | `active`, `paused`, `archived` | Задачи генерируются только для `active` |
| `start_date` | дата | Начало обслуживания |

## Расшифровка режимов

- `УСН-Д` — УСН «доходы»
- `УСН-ДР` — УСН «доходы минус расходы»
- `ОСНО` — общая система
- `ПСН` — патент (только для ИП; совмещается с УСН — указывайте основной режим, патент отмечайте признаком в CRM)
- `АУСН` — автоматизированная УСН
- `ЕСХН` — единый сельскохозяйственный налог

## Тарифы и объём услуг

| Тариф | Что входит | Что не входит |
|---|---|---|
| **Базовый** | Учёт, налоги, обязательная отчётность, ЕНС | Зарплата, кадры, отчёт клиенту, налоговое планирование |
| **Стандарт** | Базовый + зарплата и кадры + ежемесячный отчёт клиенту | Налоговое планирование, квартальные встречи, восстановление учёта |
| **Полный** | Стандарт + налоговое планирование + квартальные встречи + приоритетная поддержка | Представительство в суде, налоговые проверки (отдельный договор) |

Тариф не влияет на генерацию задач напрямую — обязательная отчётность сдаётся всем.
Он ограничивает сервисные задачи (`CLI-*`): если по договору отчёт клиенту не предусмотрен,
уберите `CLI-10` для этого клиента исключением в CRM или заведите отдельный каталог для тарифа.

## Регламент актуализации карточки

Карточка обновляется **в день, когда стало известно об изменении**, а не в конце месяца.

| Событие | Кто вносит | Срок | Что перепроверить |
|---|---|---|---|
| Принят первый сотрудник | Зарплатный бухгалтер | В день приказа | `employees`, `advance_day`, `salary_day`; появляется весь блок зарплаты и ЕФС-1 в тот же месяц |
| Уволен последний сотрудник | Зарплатный бухгалтер | В день приказа | Отчётность за период до увольнения сдаётся до конца года |
| Переход на НДС / утрата освобождения | Ведущий бухгалтер | В день получения информации | `nds`, счета-фактуры, книги покупок и продаж, авансы |
| Смена режима налогообложения | Главный бухгалтер | В день подачи уведомления | `sno`, переходные положения, доходы и расходы переходного периода |
| Открыта касса | Ведущий бухгалтер | В день регистрации ККТ | `kassa`, подключение ОФД к сверке |
| Первая внешнеэкономическая сделка | Ведущий бухгалтер | До первого платежа | `ved`, постановка контракта на учёт в банке |
| Приобретено ОС / транспорт / земля | Ведущий бухгалтер | В месяце приобретения | `prop`, авансы по имущественным налогам |
| Открыто обособленное подразделение | Главный бухгалтер | В день постановки на учёт | `op`, раздельная уплата НДФЛ |
| Смена ответственного | Руководитель отдела | В день решения | `accountant` / `payroll`, уведомление клиента |
| Приостановка обслуживания | Руководитель отдела | В день решения | `status` = `paused`, закрытие незавершённых периодов |

**Контроль:** задача `INT-30` (планирование на следующий месяц) включает сверку
карточек клиентов с фактическим положением дел. Раз в квартал главбух делает
сплошную сверку профилей с данными ЕГРЮЛ/ЕГРИП и личного кабинета ФНС.

## Типовые профили

| Профиль | Настройки | Примерный объём задач в месяц |
|---|---|---|
| ИП на УСН без сотрудников | `ИП`, `УСН-Д`, `employees=0` | 12–14 |
| ИП на УСН с сотрудниками | `ИП`, `УСН-ДР`, `employees>0` | 25–30 |
| ООО на УСН без НДС | `ООО`, `УСН-Д`, `nds=0` | 28–32 |
| ООО на УСН с НДС | `ООО`, `УСН-Д`, `nds=1` | 32–38 |
| ООО на ОСНО | `ООО`, `ОСНО`, `nds=1` | 36–42 |
| ООО на ОСНО с ВЭД и ОС | `ООО`, `ОСНО`, `ved=1`, `prop=1` | 40–46 |

Цифры получены на демо-справочнике `data/clients.sample.csv` — сверьте со своим
после первой генерации, это база для расчёта нагрузки и себестоимости клиента.

## Аудит заполненности

Проверка справочника — своего или выгрузки из CRM:

```bash
python3 tools/audit_clients.py --file export_crm.csv
python3 tools/audit_clients.py --file export_crm.xlsx --compare data/clients.csv
```

Колонки распознаются по русским заголовкам автоматически; если заголовок нестандартный,
передайте явное сопоставление: `--map mapping.json` вида `{"sno": "Режим НО"}`.

Что проверяется:

| Проверка | Почему это важно |
|---|---|
| Обязательные поля пусты (`opf`, `sno`, `nds`, `employees`, `accountant`) | Задачи сгенерируются неполно или уйдут не тому исполнителю |
| Признаки не заполнены (`kassa`, `ved`, `prop`, `mark`, `alco`, `op`) | Пусто ≠ «нет»: незаполненный признак молча отключает целый блок задач |
| ИНН: контрольная сумма, длина по ОПФ, дубли | Неверный реквизит в отчётности, задвоение задач |
| ПСН у ООО | Патент применим только для ИП — неверный налоговый блок |
| ОСНО без признака НДС | Не сформируются декларация и уплата НДС |
| Сотрудники есть, но нет зарплатного бухгалтера или дней выплат | Зарплатные задачи встанут по умолчанию, риск нарушения ТК РФ |
| Нет главного бухгалтера | Не будет задач контроля качества и налогового планирования |
| Нет даты начала обслуживания | Не отделить наши периоды от периодов предыдущего бухгалтера |
| Расхождение состава клиентов с нашим справочником | Клиент обслуживается, но задач по нему нет — или наоборот |

Отдельно отчёт показывает, **каких полей в выгрузке нет вообще**. Это главный
результат аудита: если признак нигде не хранится, соответствующие задачи
не могут генерироваться автоматически ни при какой настройке CRM.

Отчёты: `out/audit_clients.md` (сводка) и `out/audit_clients.csv` (построчно, для работы).
