# Чек-лист заполненности Finkoper

Источник — официальные инструкции Finkoper: <https://finkoper.com/ru/blog/oglavlenie/>.
Здесь они переведены в проверяемый список: **что должно быть заполнено, где именно,
и какая функция перестаёт работать, если поле пустое**.

Логика документа одна: в Finkoper задача по клиенту рождается не из желания бухгалтера,
а из данных карточки. Пустое поле — это не «неаккуратность», это **не созданная задача**.

Уровни:

- **Критично** — без этого задачи не создаются или создаются неверно.
- **Важно** — задачи создаются, но теряется автоматизация, контроль или деньги.
- **Желательно** — удобство и аналитика.

## 1. Настройки компании (делается один раз)

| Что | Где в Finkoper | Уровень | Что сломается, если пусто |
|---|---|---|---|
| **Роли сотрудников** созданы (Ведущий бухгалтер, Зарплатный, Главбух, Помощник) | Настройки → Настройки компании → Роли сотрудников | Критично | Автозадачи по отчётности нельзя адресовать роли — всё падает на одного ответственного |
| **Роль проставлена каждому сотруднику** | Настройки → Сотрудники | Критично | То же: автоматические задачи не находят исполнителя |
| **Собственные поля** заведены (перечень — в `data/finkoper_custom_fields.csv`) | Настройки → Настройки компании → Собственные поля в карточке клиента | Критично | Признаки профиля (НДС, ВЭД, касса, маркировка, ОП) негде хранить → нечем управлять составом задач и нечего выгружать на аудит |
| У признаков профиля включён флаг **«Обязательное»** | там же, при создании поля | Важно | Новый клиент заводится с пустым профилем, ошибка вскрывается через месяц |
| **Шаблоны задач** созданы для месячного контура | Настройки → Настройки компании → Шаблоны задач | Важно | Рутина заводится руками, чек-листы и приоритет теряются |
| **Теги клиентов** заведены (отрасль, статус, группа риска) | Настройки → Настройки компании → Теги клиентов | Желательно | Нет быстрой выборки клиентов по признаку |
| **Тарифы** созданы и настроены (ОПФ, количество операций, сотрудники, доп. услуги) | Настройки → Тарифы | Важно | Не считается «тариф по факту» → рентабельность клиента неизвестна |
| **Получатель оплаты** (своя компания) заведён | Настройки, раздел счетов | Важно | Счета клиентам не формируются |
| **Прайс-лист** заполнен | Аналитика → Анализ клиентов и тарифов → Прайс-листы | Желательно | Нет источника цен для допуслуг и генерации документов |
| **Шаблоны документов DOCX** с переменными загружены | Генерация документов | Желательно | Договоры и доверенности готовятся вручную |
| **База знаний по клиентам** создана (её можно создать **только одну** на бухкомпанию) | База знаний, тип «по клиентам» | Важно | Инструкции по клиенту живут в головах и личных папках |
| **ПИН-коды сотрудникам** (4 цифры) для шифрованных полей | Настройки → Сотрудники | Важно | Пароли, ЭЦП и доступы клиентов лежат в открытом виде |
| **Оклад каждого сотрудника** | Настройки → Сотрудники | Важно | Не считается себестоимость часа → отчёт по рентабельности пустой |

## 2. Карточка клиента — основные сведения

| Поле | Уровень | Что сломается, если пусто |
|---|---|---|
| **ИНН** | Критично | Отваливается сразу четыре механизма: сопоставление статусов из 1С-Отчётности («без ИНН система не сможет сопоставить клиента»), проверка статистической отчётности, автозаполнение реквизитов при генерации документов, кнопки «Выписка / Финансы / Связи» |
| **Название** | Критично | Клиента не найти, задачи не сгруппировать |
| **Представитель клиента** (ФИО) | Важно | Некому адресовать запрос документов, не работает персональный Telegram-бот |
| **E-mail представителя** | Критично для почты | Письмо не привязывается к клиенту и не попадает в его чат. Инструкция прямо предупреждает: «Обратите внимание на корректность адреса электронной почты!» |
| **Телефон** | Важно | Не привязывается чат WhatsApp |
| **Ответственные бухгалтеры** | Критично | Клиент не виден сотруднику в списке, автозадачи не адресуются |
| **Роль каждого ответственного** (ведущий / зарплатный / главбух) | Критично | Зарплатные задачи уходят ведущему, контроль качества — никому |
| **Номер и дата договора** (реквизиты) | Важно | Не формируется счёт за месяц, не подставляются переменные в документы |
| **Статус клиента** (активен / архив) | Важно | По расторгнутым клиентам продолжают создаваться задачи |

## 3. Карточка клиента — блок задач

| Что | Где | Уровень | Что сломается, если пусто |
|---|---|---|---|
| **День выплаты аванса** | Общая → Периодические задачи | Критично при наличии сотрудников | Не создаётся задача на аванс; нарушение ст. 136 ТК РФ ловится постфактум |
| **День выплаты зарплаты** | там же | Критично при наличии сотрудников | То же по зарплате и НДФЛ |
| **«Перенос»** — сдвиг даты на N рабочих дней | Настройки задач и ролей (по каждому отчёту), Периодические задачи, Патенты | Важно | Задача появляется в календаре в день законного срока. Буфера на протокол об ошибке из ФНС нет. Важно: перенос меняет **только дату отображения в календаре**, законный дедлайн остаётся прежним |
| **Статус отчёта** (переключатель ненужных задач) | Настройки задач и ролей | Важно | Клиенту на УСН прилетает декларация по НДС — и наоборот, отключённое «на всякий случай» не прилетает вообще |
| **Ответственный по каждому типу отчёта** (через роль) | Настройки задач и ролей | Критично | Автозадача создаётся без исполнителя |
| **Патенты**: название, срок действия, сумма, комментарий | Общая → Патенты | Критично для ИП на ПСН | Нет автозадач на оплату патента, продление и уменьшение суммы на взносы — это прямые деньги клиента |
| **Наблюдатель** на задачах категории A | В задаче / шаблоне | Желательно | Главбух не узнаёт о завершении критичной задачи |
| **Чек-лист** в задаче | Шаблон задачи | Важно для категории A | Задача закрывается «на глаз», контроль качества не воспроизводим |
| **Приоритет** | Шаблон задачи | Важно | Не работает правило эскалации, «красная зона» пустая |

## 4. Деньги: тариф, тайминг, рентабельность

| Что | Где | Уровень | Что сломается, если пусто |
|---|---|---|---|
| **Тариф назначен клиенту** | Тарифы → Назначить тариф | Важно | Нет «тарифа по факту», отклонение от договора не видно |
| **Сумма по договору** | Тарифы → Назначить тариф, графа «Тариф по договору» | Важно | Не с чем сравнивать фактический объём работ |
| **Финансы в задаче** (услуга, единица измерения, стоимость) | В задаче → Финансы | Желательно | Допуслуги не попадают в счёт и в расшифровку за месяц |
| **«Добавить в счёт за месяц»** у платных допзадач | В задаче | Важно | Работа сделана, деньги не выставлены |
| **Тайминг** (таймер в задаче) | В задаче / Фотография дня | Важно | Не считается себестоимость обслуживания, почасовые услуги не пересчитываются, отчёт «Фотография рабочего дня» пустой |

Формула, по которой Finkoper считает прибыль по клиенту:
**Сумма по договору + Доп − Себестоимость**, где себестоимость = расходы на сотрудника ÷ количество часов.
Пустой оклад сотрудника или невёденный тайминг обнуляют всю ветку аналитики.

## 5. Каналы и интеграции

| Что | Уровень | Что даёт |
|---|---|---|
| **Почта подключена**, ящик синхронизирован | Важно | Письма автоматически раскладываются по клиентам — по e-mail из карточки |
| **Telegram-бот клиента** (личный или групповой) | Важно | Переписка и документы внутри CRM, клиент видит задачи; настраивается флагами «информировать о завершении задач», «запретить создавать задачи» |
| **WhatsApp**, чат привязан к клиенту | Желательно | Тот же канал для тех, кто не в Telegram |
| **Telegram-уведомления сотруднику** | Важно | Бухгалтер узнаёт о новой задаче за 1–2 минуты, а не при открытии CRM |
| **1С-Отчётность** (токен и секретный ключ) | Важно | Задача автоматически завершается, когда ФНС принимает отчёт. Требует ИНН в карточке |
| **Контур.Экстерн / СБИС** | Важно | Статусы документооборота видны прямо в задаче; календарь подсвечивает отправленные, принятые и просроченные |
| **Entera** | Желательно | Первичка уходит на распознавание в один клик |
| **Яндекс.Диск** | Желательно | Общее хранилище инструкций и нормативки с правами по сотрудникам |
| **Быстрые кнопки в карточке** (ссылки на облачные базы 1С) | Желательно | Бухгалтер попадает в базу клиента из карточки, а не ищет ссылку в переписке |

## Как проверить свою базу

**Шаг 1.** Выгрузите клиентов: Настройки → Клиенты → Экспорт клиентов в XLSX.

**Шаг 2.** Прогоните две проверки:

```bash
python3 tools/audit_finkoper.py --file export_clients.xlsx   # заполненность CRM по этому чек-листу
python3 tools/audit_clients.py  --file export_clients.xlsx   # пригодность профиля для генерации задач
```

Если Python ругается на отсутствие `openpyxl` — либо `pip install openpyxl`,
либо сохраните выгрузку из Excel как CSV и подайте её тем же ключом `--file`.

**Шаг 3.** Скрипт печатает, сколько полей чек-листа он распознал в выгрузке.
Колонки, которые он не понял, он перечисляет отдельно. Если среди них есть поле
из чек-листа, назовите его явно:

```bash
echo '{"email": "Почта клиента", "shift": "Сдвиг срока"}' > mapping.json
python3 tools/audit_finkoper.py --file export_clients.xlsx --map mapping.json
```

Первый скрипт отвечает на вопрос «что не заполнено в Finkoper»,
второй — «какие задачи из-за этого не сформируются».

Отчёты складываются в `out/`: сводка в `.md`, построчный список замечаний в `.csv`
(его удобно раздать бухгалтерам как список на исправление).

> Экспорт не содержит зашифрованных собственных полей — по инструкции
> «при экспорте собственных полей зашифрованные данные не выгружаются».
> Их заполненность проверяется только глазами в интерфейсе.

Раздел «Полей нет в CRM» в отчёте — самый важный. Он означает не пустое значение
у одного клиента, а отсутствующее поле: связанная с ним автоматизация Finkoper
не работает ни по кому. Такие пробелы закрываются одним действием администратора,
а не обходом всех карточек.

## Порядок устранения пробелов

1. **Критично по всем клиентам** — сначала ИНН, ответственные и роли, режим налогообложения, НДС, численность.
   До их заполнения генерировать план на месяц бессмысленно.
2. **Настройки компании** — роли, собственные поля, шаблоны. Один раз, силами администратора.
3. **Важно по клиентам** — переносы, дни выплат, патенты, договор, тариф.
4. **Деньги и аналитика** — оклады, тайминг, назначение тарифов.
5. Повторный прогон аудита. Норма — ноль замечаний уровня «Критично» перед каждой
   ежемесячной генерацией плана (см. [SLA и контроль](06-sla-control.md)).
