# Роли и зоны ответственности

## Матрица ролей

| Код | Роль | Ведёт задачи | Не делает |
|---|---|---|---|
| `ASSIST` | Ассистент бухгалтера | Сбор и обработка первички, ЭДО, архив, акты и счета клиенту, контроль ЭЦП | Не считает налоги, не общается с клиентом по методологии |
| `ACCT` | Ведущий бухгалтер клиента | Учёт, налоги, отчётность, ЕНС, текущая коммуникация с клиентом | Не меняет учётную политику без согласования |
| `PAYROLL` | Бухгалтер по расчёту зарплаты | Зарплата, НДФЛ, взносы, кадровый учёт, ЕФС-1, РСВ, 6-НДФЛ | Не ведёт основной учёт клиента |
| `CHIEF` | Главный бухгалтер-методолог | Контроль качества, методология, годовая отчётность, налоговое планирование | Не ведёт клиентов операционно |
| `HEAD` | Руководитель отдела | Планирование, нагрузка, SLA, эскалации, ресурсы | Не является арбитром по методологии |

Коды ролей используются в `data/task_catalog.csv` (колонка `role`) и определяют,
на кого из карточки клиента ложится задача.

## Как роль превращается в конкретного человека

В карточке клиента (`data/clients.sample.csv`) три поля с фамилиями:

- `accountant` — ведущий бухгалтер, получает задачи `ASSIST` и `ACCT`
- `payroll` — зарплатный бухгалтер, получает задачи `PAYROLL`
- `chief` — главный бухгалтер, получает задачи `CHIEF` и `HEAD`

Если поле `payroll` пустое, зарплатные задачи уходят ведущему бухгалтеру.
Это штатная ситуация для мелких клиентов без сотрудников.

## Принцип одного ответственного

У задачи ровно один исполнитель. «Ответственные: Иванова и Петрова» запрещено —
это гарантированная просрочка. Если задача требует двух человек, она делится на две
задачи с разными сроками: например, `PAY-20` (расчёт, зарплатный бухгалтер) и
`PAY-30` (реестр на выплату, он же) — а проверка идёт отдельной задачей `QC-10` (главбух).

## Подмена на время отсутствия

| Ситуация | Действие |
|---|---|
| Плановый отпуск | За 5 рабочих дней до отпуска руководитель отдела массово меняет исполнителя в задачах периода. Передача — по чек-листу `checklists/planning.md` |
| Больничный до 3 дней | Задачи категории A переназначаются в день получения информации, остальные ждут |
| Больничный свыше 3 дней | Полная передача клиента подменному бухгалтеру с брифингом от главбуха |
| Увольнение | Передача по акту: доступы, статус задач, открытые вопросы клиента, незакрытые периоды |

**Правило:** клиент не должен узнавать об отпуске своего бухгалтера из-за срыва срока.
Уведомление клиента о подмене — обязательная задача при передаче.

## Эскалация по уровням

```
Бухгалтер
   │ методологический вопрос, спорная операция
   ▼
Главный бухгалтер ──── ответ в течение 1 рабочего дня
   │ вопрос требует решения на уровне агентства / риск доначислений
   ▼
Руководитель отдела ── решение в течение 1 рабочего дня
   │ риск утраты клиента / претензия / сумма риска свыше 500 тыс. руб.
   ▼
Руководитель агентства
```

Отдельно: **клиент не предоставляет документы** — это не методологическая, а договорная
эскалация, идёт по ветке бухгалтер → руководитель отдела, см. [эскалации](08-escalations.md).
